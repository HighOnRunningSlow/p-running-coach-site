P Running Coach

Privacy policy

How the application connects Garmin data with Google Sheets and optional Google Drive storage.

Effective date: 22 November 2026.

Scope and operator

P Running Coach is a personal-use application operated by HighOnRunningSlow to organize the operator's own training data. It is not currently offered as a public account-based service. It retrieves data through Garmin's official Connect Personal API, organizes it in a configured Google spreadsheet and can store supported original FIT files in Google Drive.

Operator and website publisher: HighOnRunningSlow. Privacy and deletion contact: highonrunningslow@gmail.com.

This public information website does not connect to Garmin or Google accounts and requires no authentication. Application authorization is configured separately.

Data accessed

Garmin activities and wellness

Depending on configuration and availability, the application retrieves activity identifiers, names, sport types, dates and times, distance, duration, elevation, pace, heart rate, cadence, power, device information and Garmin training or performance measurements. Imports can include multiple sports and historical activities.

When wellness synchronization is enabled, it retrieves available daily stress, heart-rate ranges and resting heart rate, HRV, sleep duration, stages and score, Body Battery, steps, calories, intensity minutes, respiration, oxygen saturation, hydration, and weight or body-composition measurements.

When original-file processing is enabled, it downloads available activity originals and parses supported FIT files. These may contain GPS coordinates, timestamps, device information and detailed physiological samples. GPS samples are processed in memory and are not written as GPS rows in Sheets. Stored original FIT files may retain those details.

Google data

The application reads its configured spreadsheet's application tabs, including imported records, summaries, training plans, race goals and synchronization history. It writes imported data and calculations and updates linked training-plan actual results.

For optional FIT storage, it searches the configured Drive folder for matching filenames, reads matching file identifiers and creates or updates FIT files. The setup helper creates a Drive folder.

Credentials and operational information

The application uses a Garmin API key and Google OAuth credentials, including a refresh token for unattended access. A service-account credential is supported as an alternative. Operational records include run times, date ranges, counts, statuses, checkpoints and error categories.

Google permissions

The OAuth setup helper requests both scopes below:

https://www.googleapis.com/auth/spreadsheets
This permits viewing, editing, creating and deleting spreadsheets accessible to the authorized account. It is broader than a single spreadsheet. The reviewed synchronization code targets the configured spreadsheet and does not enumerate other spreadsheets.
https://www.googleapis.com/auth/drive.file
This permits access to specific Drive files created by or made available to the application, rather than unrestricted access to all Drive files. The implementation uses it for the FIT folder and original-file storage.

At runtime, the credential adapter requests the Sheets scope and adds the Drive scope when FIT uploads are configured. The one-time helper requests both. It requests offline access so scheduled jobs can refresh authorization without repeated consent.

The reviewed code does not request Gmail, Contacts, Calendar or Google sign-in profile scopes. See Google's Sheets scope documentation and Drive scope documentation.

Purpose and use

  • Maintain a structured activity and wellness history.
  • Calculate running summaries, all-sports workload and performance trends.
  • Extract laps and calculate clearly labelled running estimates.
  • Fill actual results for training-plan entries linked to activities.
  • Support incremental updates, historical imports and troubleshooting.
  • Keep supported original FIT files when enabled.

The reviewed pipeline does not call an LLM API or send data to an AI model. If you separately share spreadsheet data with an LLM, AI assistant or coach of your choice, that access is governed by your separate connection or export, sharing choices and the recipient's terms.

Missing measurements remain blank. Calculated estimates are distinct from Garmin measurements. The application provides training context, not medical diagnosis.

Storage, access and sharing

  • Google Sheets: activity and wellness records, derived summaries, plans, goals and synchronization history.
  • Google Drive: supported original FIT files when uploads are configured.
  • GitHub Actions: cloud execution, repository secrets and operational logs. Garmin responses and FIT data pass through runner memory.
  • Optional local setup: the OAuth helper writes a credential file locally. The optional inspection command can save a real activity validation file locally.

Google and GitHub process data involved in providing these services; Garmin supplies the source records. People with access to the spreadsheet, Drive folder, repository or configured credentials may have access according to their permissions.

The reviewed application does not create public sharing permissions. Existing and inherited Google sharing settings still apply. This public information website does not publish the private training database.

The operator uses application data for personal training analysis and application operation, not for advertising, selling data or training AI models. Optional sharing with a coach, LLM or AI assistant is a separate choice made by the operator, as described above. The application does not automatically send data to those recipients. Their own terms govern any data shared with them.

Retention and deletion

The reviewed application has no automatic retention expiry or account-wide deletion function. Imported records and uploaded files remain in their configured destinations until removed. Revoking access does not delete previously stored copies.

Activity history, wellness records, summaries and original FIT files are retained for long-term personal training analysis until the operator chooses to delete them. Credentials are kept while needed for the connection and should be removed when it is discontinued. Operational logs follow the configured GitHub retention settings; the application does not impose a separate automatic expiry. Any separately retained local copies or backups require separate deletion.

For privacy questions or to request deletion of data held by the operator, email highonrunningslow@gmail.com and identify the relevant data to remove. Requests are handled manually; this policy does not promise a fixed completion deadline. Do not post passwords, API keys, tokens or health records in public GitHub issues.

If you control the installation, disable synchronization workflows first to prevent reimport. Remove the relevant spreadsheet data or spreadsheet, original FIT files and any local validation copies. Permanently delete items from Drive's trash when appropriate. Remove stored credentials and review retained workflow logs and any backups separately.

Deleting application copies does not delete original Garmin Connect records. Provider-managed backups and retention are subject to the relevant provider's policies.

Revoke access

Google OAuth

  1. Open your Google Account's third-party connections.
  2. Select the Google Cloud application used to authorize this installation. Its consent-screen name may differ from this website's name.
  3. Review its access and remove the connection or access permission.

This stops future access through that authorization but does not erase stored data. Also disable scheduled jobs and remove stored OAuth credentials. See Google's access-management guidance.

For a service account, remove its spreadsheet sharing access and revoke or delete its credential as appropriate.

Garmin

Revoke or replace the Personal API key through Garmin's account/API-key controls and remove it from the installation. This does not delete records already copied to Google.

This public website

These static pages contain no forms, sign-in, JavaScript, analytics, tracking pixels, external fonts or embedded third-party content. They do not set application cookies or store fitness data in your browser.

GitHub Pages handles website requests and may process technical request information under GitHub's privacy statement. External links are subject to their destinations' practices.

Policy updates

This policy will be reviewed when permissions, data uses, storage destinations or operator practices change, and before the application is offered to other users. The effective date above identifies this version.
